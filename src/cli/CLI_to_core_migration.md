# CLIからCoreへ移設すべき機能のメモ

CLIでのみ実装されているが、WebAssembly版でも再利用したい処理を洗い出した。
各項目は既存の`msx1pq_cli.cpp`内の実装箇所と、Core側に移す理由・期待するAPIの形を示す。

## 量子化パイプライン（`quantize_image`）
- **概要**: RGBA配列と`CliOptions`を受け取り、プリプロセス・量子化・8dot処理をまとめて実行している。既存のCore APIを組み合わせた高レベル処理のハブになっている。
- **場所**: `src/cli/msx1pq_cli.cpp` の `quantize_image` 実装（約L430-L525）。
- **移設理由**: WASM版でもRGBAバッファを直接受けて同じ処理を行いたい。Coreに移すことで、CLI/WASM/他ツールが同じ高レベル関数を共有できる。
- **期待する形**: `MSX1PQCore::QuantInfo` を受け取って `std::vector<RgbaPixel>` をインプレース更新するユーティリティ関数としてCoreへ昇格。プリプロセス有無・8dot種別・ダークディザーの適用などを引数で切り替えられるようにする。

## 出力画像スケーリング（`scale_pixels`）
- **概要**: 量子化後のRGBA配列を整数スケールで拡大する簡易最近傍スケーリング。
- **場所**: `src/cli/msx1pq_cli.cpp` の `scale_pixels` 実装（約L528-L548）。
- **移設理由**: WASM UIでも拡大表示用に同じロジックを使い回すため。Coreに置くことで、出力形式に依存しない共通ユーティリティとして扱える。
- **期待する形**: `std::vector<RgbaPixel>` と幅・高さを参照で受け取り、整数スケールを適用する汎用関数。RGBA型もCoreで定義し、CLI/WASM双方が共有する。

## パレットPNG書き出し（`write_palette_png`）
- **概要**: 量子化済みRGBA配列をMSX1/2の16色パレット付きPNGとしてエンコードする。パレット選択や透明色の付与を含む。
- **場所**: `src/cli/msx1pq_cli.cpp` の `write_palette_png` 実装（約L550-L600 以降）。
- **移設理由**: WASM版でも量子化結果をダウンロード／保存する際に同じエンコード処理が必要。Coreに移すことで、出力形式をCLI依存から切り離し、API経由でPNGバイナリを取得できるようにする。
- **期待する形**: 出力先パスに依存しないよう、`std::vector<unsigned char>` のPNGバイト列を返すAPI、またはストリーム/コールバックに書き出すAPIをCoreに提供する。

## SCREEN2バイナリ生成（`write_sc2`）
- **概要**: 256x192キャンバスを組み立て、パターン/カラー/ネームテーブルを構築してBSAVE形式の`.sc2`バイナリを書き出す。
- **場所**: `src/cli/msx1pq_cli.cpp` の `write_sc2` 実装（約L600-L735）。
- **移設理由**: CLI以外でもSC2出力をサポートするため。WASMからダウンロードできる形で出力を生成するには、ファイルI/Oに依存しないCore関数として切り出す必要がある。
- **期待する形**: RGBA配列と出力オプションを受け取り、`std::vector<std::uint8_t>` のVRAMバッファやBSAVEバイト列を返すCore API。

## 入力PNG読み込みとRGBA変換（`process_file` 前半）
- **概要**: `lodepng`でPNGを読み込み、RGBA配列を作成するまでの共通処理。
- **場所**: `src/cli/msx1pq_cli.cpp` の `process_file` 冒頭（約L737-L758）。
- **移設理由**: WASM版でもPNGデータ（ArrayBufferなど）からRGBA配列への変換が必要。Coreに依存関係を集約することで、CLI/WASM双方で同じデコードと入力検証を再利用できる。
- **期待する形**: バッファ入力（ファイルパスではなくメモリ）からRGBA配列を返す関数、またはデコード済みRGBAを受け取って以降の処理を行う高レベル関数。

## 入力走査のユーティリティ（`collect_inputs`）
- **概要**: フォルダを走査してPNGだけを列挙する単純なヘルパー。
- **場所**: `src/cli/msx1pq_cli.cpp` の `collect_inputs` 実装（約L770-L783）。
- **移設理由**: WASM側でディレクトリ走査は不要だが、将来的にバッチ入力を共有する際にCLI専用実装のままだと重複が増える。Coreに置き、プラットフォーム別の入力ソース実装に差し替えられるようにする検討材料として記載。
- **期待する形**: I/O依存を排したインターフェースにし、プラットフォーム固有の入力取得ロジックを差し替えられるよう抽象化する。
